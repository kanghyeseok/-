# 예산안 사업 쟁점 도출 (budget-issue-extractor)

목표: 사업 1건마다 **의원이 그대로 읽고 질의·조정할 수 있는** 쟁점 2~4개를 만든다.
원문에 없는 수치·발언은 절대 만들지 않는다. 확인 못 한 것은 `[확인 필요]`로 남긴다.

## 입력
사업별 원문 3종 (HTML·PDF·텍스트 어느 형식이든 가능)
1. 사업설명서 원문
2. 전문위원 검토보고 원문
3. 예산안 조정 원문(상임위·예결위 조정 내역, 부대의견)

파일 안에 "정답 쟁점"이나 분석관 의견이 있으면 **작성할 때는 가리고**, 다 쓴 뒤 채점할 때만 쓴다.

## 절차

### 1. 원문 구조화 (사업별 메모 작성)
- **사업설명서**: 사업목적, 법적근거, 총사업비·연차계획, 전년 예산 → 금년 요구액(증감액·증감률), 산출근거(단가×수량×기간), 신규/계속, 재원(국비·시비·구비), 성과지표·목표치, 전년 집행실적
- **검토보고**: 전문위원 지적을 문장 단위로 뽑고 체크리스트 번호(①~⑩)로 태깅. 쪽수 기록
- **조정안**: 감액/증액 금액, 조정 사유, 부대의견
- 모든 수치에 출처(문서·쪽·표) 표시

### 2. 체크리스트 점검
`references/issue-checklist.md`의 10개 항목마다 **해당 / 비해당 / 정보부족**을 판정하고 근거를 한 줄 적는다.
법령 근거는 `korean-law` MCP(`search_law` → `get_law_text`, 조례는 `execute_tool` 안의 `search_ordinance`)로 **현행 조문을 확인한 뒤에만** 인용한다.

### 3. 원문 간 정합성 대조 (가장 강한 쟁점 신호)
| 신호 | 쟁점 유형 |
|---|---|
| 검토보고는 지적했는데 조정안에 반영 안 됨 | 미해소 쟁점 → 추가 조정 근거 |
| 조정안은 감액했는데 검토보고 근거가 약함 | 감액 사유 보강 필요 |
| 사업설명서 수치 ≠ 검토보고 수치 | 사실확인 쟁점 |
| 산출근거 합계 ≠ 요구액 | 산출 오류 |
| 성과지표가 산출(output)뿐이고 결과(outcome) 없음 | 성과관리 쟁점 |

산식은 직접 다시 계산해서 확인한다(합계, 증감률, 집행률 = 집행액/예산현액).

### 4. 회의록·외부 근거 보강 (가능할 때만)
- 검색어: `"사업명" 2027년도 예산안 <소관 상임위>`, `"사업명" 결산`, `"사업명" 행정사무감사`
- 우선 출처: 서울시의회 회의록(council.seoul.go.kr), 지방의회 회의록 통합검색(clik.nanet.go.kr), 서울시의회 보도자료
- 인용은 **회차·회의명·일자·발언자**를 모두 확인한 발언만. 직접 확인 못 하면 인용하지 않고 "회의록 확인 필요"로 적는다.
- 접속이 막혀 있으면 사용자에게 알리고 원문 3종만으로 진행한다.

### 5. 쟁점 선정 (사업당 2~4개)
중요도 = 금액 규모 × 위법·절차 하자 여부 × 반복 지적 여부 × 조정 연결성.
비슷한 쟁점은 합치고, 조정 의견으로 이어지지 않는 단순 권고는 뒤로 미룬다.

### 6. 작성
`references/output-template.md` 양식을 그대로 따른다. 사업마다 맨 앞에 **1쪽 요약 카드**를 둔다.

### 7. 자체 검수
`references/quality-rubric.md`로 점수를 매기고, 미달 항목은 고쳐 쓴다. 정답지가 있으면 적중률을 기록한다.

## 문체
- 행정 보고서 문체(개조식, "~임", "~필요함"). 쟁점 제목은 결론이 드러나는 한 문장.
- 질의문은 존댓말 구어체로, 실·국장이 구체적 숫자나 일정으로 답하도록 묻는다("~하십니까?"로 끝나는 예/아니오형 질문 금지).
- 단위는 백만원(원문 단위가 다르면 원문 단위를 따르고 명시).
