# seoul_council_PoC — 작업 규칙

서울시의회 예산안 심사 지원(사업별 쟁점 도출) PoC 프로젝트. 이 폴더에서 Claude Code를 열면 아래 규칙과 프로젝트 스킬 `budget-issue-extractor`가 적용된다.

## 무엇을 하는 프로젝트인가
- 예산안 원문(전문위원 검토보고 · 사업설명서 · 의회 조정내역)으로 사업별 **쟁점**을 의원이 바로 쓸 수 있는 수준으로 작성한다.
- 결과를 전문가 정답지와 같은 분류(쟁점 종류·결론·중요도·출처)로 태그해, AI 분석과 전문가 판단을 비교한다.

## 스킬
- 쟁점 작성은 항상 `.claude/skills/budget-issue-extractor/`를 따른다(`/budget-issue-extractor`로 호출).
- 사용자가 쟁점 개수를 정하면 그 개수를 따르고, 핵심 3개 + 추가 쟁점의 2단 구조로 쓴다.
- 스킬을 고치면 `평가/`에 새 회차(`스킬평가_2차` …)를 만들어 이전과 비교하고, `공유/budget-issue-extractor.skill`을 다시 패키징한다.

## 폴더와 파일 규칙
| 폴더 | 넣는 것 | 규칙 |
|---|---|---|
| `자료/원본/` | 사용자가 준 원본 파일 | **수정하지 않는다.** 새 연도·새 묶음은 파일명에 연도·회차를 붙여 추가 |
| `자료/원문이미지/` | 원본에서 뽑은 쪽 이미지·`meta.json` | `스크립트/extract.py`로만 만든다 |
| `쟁점보고서/` | 사업별 보고서 `pNN_사업명.md`, `00_종합.md`, `ai_쟁점_태그.json` | 사업별 보고서가 원본, 종합·JSON은 스크립트로 다시 만든다 |
| `정답지_AI초안/` | AI 쟁점을 채운 정답지 HTML | 전문가에게 보내는 정답지로 쓰지 않는다(아래 주의) |
| `계획/` | 작업 계획서 | 날짜·주제를 파일명에 |
| `평가/` | 스킬 평가 회차별 결과 | 회차마다 새 폴더 |
| `공유/` | 배포용 `.skill` 패키지 | 스킬 수정 후 갱신 |
| `스크립트/` | 재사용 스크립트 | 경로는 이 폴더 기준 상대경로 |

## 작업 순서 (새 정답지·새 사업 묶음이 들어왔을 때)
```bash
# 1) 원본을 자료/원본/에 두고 쪽 이미지 추출
python3 -I 스크립트/extract.py 자료/원본/<원본>.html 자료/원문이미지
# 2) 사업별로 이미지를 읽고 /budget-issue-extractor 로 쟁점보고서/pNN_사업명.md 작성
# 3) 태그 JSON과 종합본 다시 만들기
python3 -I 스크립트/build_tags.py .
python3 -I 스크립트/build_summary.py .
# 4) (요청이 있을 때만) 정답지 HTML에 AI 쟁점 채우기 — 원본은 그대로 두고 새 파일로
python3 -I 스크립트/fill_sheet.py 자료/원본/<원본>.html . 정답지_AI초안/<새파일명>.html
```
- 보고서 쟁점 머리의 태그 줄(`` `종류: …` · `결론: …` · `중요도: …` · `출처: …` ``) 형식을 지켜야 `build_tags.py`가 읽는다.

## 지켜야 할 것
- **수치는 원문 쪽수까지 추적 가능해야 한다.** 원문에 없는 숫자는 `[확인 필요]`. 검토보고 쪽수는 인쇄된 쪽 번호로 적는다(PDF 쪽과 다름).
- **회의록 발언은 직접 확인한 것만** 인용한다. 지금 환경은 `council.seoul.go.kr`, `clik.nanet.go.kr` 접속이 막혀 있어 회의록 인용 0건. 언론에 실린 발언은 `[언론]` + "회의록 원문 대조 전".
- 웹 기사 본문은 열 수 없어(WebFetch가 국내 언론 도메인 미해결) 검색 요약 기준임을 표시한다.
- 법령은 `korean-law` 도구로 현행 조문을 확인한 뒤 인용한다(예: 지방재정법 §32의2는 삭제, 시설물안전법 내진성능평가는 §12④).
- **정답지 오염 주의**: 전문가 정답은 빈 원본 정답지로 받는다. AI 초안 정답지를 전문가에게 주면 평가 기준이 AI 영향을 받는다.
