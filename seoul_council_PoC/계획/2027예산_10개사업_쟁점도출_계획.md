# 2027 서울시 예산안 10개 사업 쟁점 도출 계획

## Context
- 대상 파일(수정됨): `서울예산_사업검토_정답지_분석관용_사업설명서포함.html` (이전에 알려준 `budget-2027-ai-review-guide (1).html`은 잘못된 파일)
- 파일명에 "정답지_분석관용"이 있으므로, 파일에 이미 쟁점 정답(또는 일부)이 들어 있을 수 있음. 들어 있다면 **정답 쟁점은 AI 출력과 비교하는 채점 기준으로만 쓰고**, 스킬이 원문 3종만으로 비슷한 쟁점을 뽑아내는지 맞춰 보는 데 사용(정답을 그대로 베끼지 않음).
- 사용자(교수·연구자)가 이 파일에 10개 사업별로 **전문위원 검토보고 원문 / 사업설명서 원문 / 예산안 조정 원문**을 넣어 둠.
- 각 사업 보고서에 들어갈 **"쟁점"** 항목을 작성해야 하고, 해마다·사업마다 반복되는 작업이라 **재사용 가능한 스킬**로 만들어 두려는 것.
- 필요하면 서울시의회 회의록(상임위·예결특위 질의)을 찾아 근거로 보강.

## 현재 막힌 점 (확인 결과)
1. **파일 접근 불가**: 경로 `C:\Users\강혜석\Downloads\...`는 사용자 PC이고, 이 세션은 클라우드 컨테이너임. 저장소(`kanghyeseok/-`)에는 `칼럼/2026-10-04_100조불용액과AI예산심사.md`만 있음. desktop-commander(로컬 PC 연결)는 연결 시간 초과.
   → **해결**: HTML 파일을 저장소에 올려 주면 됨(GitHub 웹 `kanghyeseok/-` → Add file → Upload files, 브랜치 `claude/wonderful-fermi-dhzkag`, 예: `자료/서울예산_사업검토_정답지.html`) 또는 채팅에 첨부.
2. **서울시의회 사이트 직접 접속 차단**: `council.seoul.go.kr`, `smc.seoul.kr`, `clik.nanet.go.kr` 모두 환경 네트워크 정책(egress proxy)에서 거부됨.
   → **해결**: 클라우드 환경 설정 → Network access → Allowed domains에 `council.seoul.go.kr`, `clik.nanet.go.kr`(지방의회 회의록 통합검색) 추가. 추가 전까지는 WebSearch 결과(보도자료·언론)로만 보강하고, 회의록 인용은 "미확인"으로 표시(지어내지 않음).

## 추천 스킬
1. **신규 프로젝트 스킬 `budget-issue-extractor`** (핵심 추천) — `anthropic-skills:skill-creator`로 생성, 저장소 `.claude/skills/budget-issue-extractor/SKILL.md`에 커밋 → 다음 해·다른 사업에도 `/budget-issue-extractor`로 재사용.
   - 입력: 사업 1건의 3개 원문(검토보고·사업설명서·조정안)
   - 출력: 고정 양식의 쟁점 표 + 서술형 쟁점 문단
   - `references/issue-checklist.md`(아래 체크리스트), `references/output-template.md`(보고서 양식) 포함
2. **`korean-law` MCP** (이미 연결됨) — 지방재정법·지방자치단체 예산편성 운영기준·서울시 조례 근거 확인 (`search_law`, `get_law_text`, `ordinance_radar`). 법적 근거·사전절차 쟁점의 사실 확인용.
3. **`anthropic-skills:deep-research` / WebSearch** — 회의록·언론·감사결과 등 외부 근거 보강.
4. (선택) 결과를 공유용으로 만들 때 `anthropic-skills:docx` 또는 Claude Docs.

## 쟁점 도출 방법 (스킬에 넣을 절차)
**1단계 — 3개 원문 구조화 추출 (사업별)**
- 사업설명서: 사업목적, 법적근거, 총사업비·연차계획, 2026 예산/2027 요구액 증감, 산출근거(단가×수량), 신규/계속, 국·시비 구성, 성과지표
- 검토보고: 전문위원 지적사항을 문장 단위로 뽑아 유형 태깅
- 조정안: 감액·증액 금액, 사유, 부대의견

**2단계 — 표준 쟁점 체크리스트로 교차점검** (각 항목: 해당/비해당/정보부족)
1. 법적 근거·사전절차: 투자심사, 타당성조사, 공유재산관리계획, 출자·출연 동의, 민간위탁 동의, 조례 근거 (지방재정법 §17·§18·§37·§37의2, 공유재산법 §10, 지방보조금법 §6 등 — §32의2는 2021년 삭제됨)
2. 사업계획 구체성·준비 정도(용역 미완료, 부지 미확보 등)
3. 집행 가능성: 전년도 집행률·이월·불용 실적
4. 산출근거 적정성: 단가·수량·비목(편성기준 위반 여부)
5. 증액·신규 사유의 타당성 / 급증 항목
6. 유사·중복 사업(본청·자치구·투자출연기관·국가사업)
7. 성과지표·성과관리 적정성
8. 재원구조: 국비 매칭, 후년도 재정부담, 운영비 전가
9. 민간보조·민간위탁 원칙 준수
10. 연례 반복 지적사항(전년 검토보고·결산 지적 미이행)

**3단계 — 3개 원문 간 정합성(쟁점의 핵심 신호)**
- 검토보고가 지적했는데 조정안에 반영 안 된 것 → "미해소 쟁점"
- 조정안에서 감액됐는데 검토보고엔 근거가 약한 것 → 감액 사유 명확화 필요
- 사업설명서 수치 ≠ 검토보고 수치 → 사실확인 쟁점

**4단계 — 회의록 보강 (가능 시)**
- 검색어: `사업명` + `2027년도 예산안` + 소관 상임위, 전년도 결산·행정사무감사 질의
- 의원 질의·집행부 답변 중 쟁점을 뒷받침하는 발언만 회차·일자·발언자와 함께 인용. 확인 못 한 것은 인용하지 않음.

**5단계 — 품질 기준: "의원이 회의장에서 바로 쓸 수 있는 수준"**
각 쟁점은 다음을 모두 갖춰야 완성으로 봄:
- **한 줄 쟁점 제목**: 결론이 드러나는 문장 (예: "전년 집행률 38%인데 2027년 예산 2배 증액 — 집행 가능성 불투명")
- **핵심 수치 3개 이내**: 요구액·증감률·집행률 등. 모두 원문 쪽수나 표 번호로 추적 가능해야 함
- **문제점**: 2~3문장. 법령·조례 조문, 편성기준 항목을 구체적으로 적음
- **의원 질의문 2~3개**: 실국장에게 그대로 읽을 수 있는 문장. 예상 답변과 재질의 포인트 포함
- **요구자료 목록**: 집행부에 제출을 요구할 자료
- **조정 의견**: 감액·삭감·부대의견 중 하나와 금액·산식. 예산안 조정 원문과 같은지, 어디가 다른지 표시
- **근거 출처**: 검토보고 p.○, 사업설명서 p.○, 회의록(회차·일자·발언자)
- 행정 문체로 간결하게. 원문에 없는 수치는 "[확인 필요]"로 표시
- 사업마다 **1쪽 요약 카드**(쟁점 제목, 질의문, 조정 의견)를 맨 앞에 둠

품질 검수(자체 점검 루브릭, 사업마다 적용): ①수치 정확성 ②근거 추적성 ③질의문이 바로 쓸 수 있는 수준인지(예/아니오로 끝나지 않고 답변을 구체적으로 요구하는지) ④조정 의견이 산식으로 뒷받침되는지 ⑤정답지와 대조한 적중률. 기준에 못 미치면 다시 작성함.

**6단계 — 우선순위·작성**
- 쟁점별 중요도(금액 규모 × 법적 문제 여부 × 반복성)로 2~4개 선정
- 양식: `쟁점 제목 → 현황(수치) → 문제점 → 근거(원문 인용·쪽수/회의록) → 의원 질의문 → 요구자료 → 조정의견`
- 원문에 없는 수치는 만들지 않고 "[확인 필요]"로 표시

## 실행 순서 (승인 후)
1. 사용자가 HTML을 저장소에 업로드 → 파일 구조 파악(10개 사업 목록, 원문 위치, 쟁점을 넣을 자리)
2. `skill-creator`로 `budget-issue-extractor` 스킬 작성·커밋
3. 사업 1개로 시범 적용 → 파일 안에 정답 쟁점이 있으면 대조해서 적중률(정답 쟁점 중 몇 개를 찾았는지, 근거 없는 쟁점이 몇 개인지) 측정 → 체크리스트·프롬프트 보정 → 사용자 검토로 양식·깊이 확정
4. 나머지 9개 사업 적용(사업별로 병렬 처리 가능)
5. 쟁점을 HTML의 해당 칸에 채워 넣은 버전 + 사업별 근거표(md)를 `claude/wonderful-fermi-dhzkag` 브랜치에 커밋·푸시

## 검증
- 각 쟁점의 모든 수치·인용이 3개 원문(또는 회의록 URL)에서 추적 가능한지 대조표로 확인
- 법령 조문은 `korean-law` MCP로 현행 조문 확인
- HTML을 Chromium으로 열어 깨짐 없이 렌더링되는지 스크린샷 확인
